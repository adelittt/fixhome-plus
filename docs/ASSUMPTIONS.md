# Dokumen Asumsi dan Keputusan Awal (Assumptions Document)
# FixHome Plus

Dokumen ini mencatat seluruh asumsi teknis dan bisnis yang digunakan dalam pengembangan sistem **FixHome Plus** berdasarkan Lampiran C BRD (PK-01 s.d. PK-19) dan PRD. Dokumen ini memastikan tidak ada asumsi yang dibuat diam-diam dan menjadi acuan verifikasi bersama.

---

| ID PK | Topik / Masalah | Asumsi & Keputusan Default Sementara (Fase 1) | Rujukan Dokumen |
| :--- | :--- | :--- | :--- |
| **PK-01** | Penyedia Pengiriman Kurir Instan | Menggunakan antarmuka kontrak adapter `ShippingServiceInterface`. Pada rilis awal (Fase 1/R1), implementasi yang aktif adalah `MockShippingService` (simulasi instan) tanpa ketergantungan API pihak ketiga riil. Penyedia pihak ketiga (Biteship/GoSend) disiapkan pada fase selanjutnya melalui adapter terisolasi. | PRD Bagian 6.4, BRD 3.8 |
| **PK-02** | Metode & Waktu Pembayaran Jasa | Pembayaran jasa dicatat dengan alur simulasi manual/sandbox (`PaymentService`), dipisah dari pembayaran marketplace. Waktu penyelesaian pembayaran jasa terjadi saat pesanan jasa ditandai `selesai` oleh teknisi dan dikonfirmasi pelanggan. | PRD Bagian 6.6 & 7, BRD 3.3 |
| **PK-03** | Pembatalan, Retur, dan Refund | Penanganan pembatalan pesanan atau refund dana diproses secara administratif manual oleh Admin di luar sistem. Sistem hanya mencatat perubahan status menjadi `dibatalkan` atau `dikembalikan_manual` beserta catatan alasan audit. Tidak ada pengembalian dana otomatis (no auto-refund). | PRD Bagian 6.6, BRD AB-012 |
| **PK-04** | Syarat Pencatatan Komisi Marketplace (2%) | Komisi marketplace dihitung dan dicatat pada saat status pesanan produk per toko mencapai status `selesai` (produk telah diterima pelanggan). Jika pesanan dibatalkan/ditolak toko, komisi tidak terbentuk atau ditandai batal. | PRD Bagian 6.5, BRD Lampiran C |
| **PK-05** | Biaya Pengiriman Multi-Toko | Biaya pengiriman dihitung per toko fisik (karena dikirim dari lokasi toko yang berbeda). Total ongkos kirim dibayar oleh pelanggan dan dicatat terpisah per toko. Ongkir **tidak pernah** menjadi dasar perhitungan komisi marketplace. | PRD Bagian 6.3, BRD AB-004 |
| **PK-06** | Sesi Pembayaran Multi-Toko | Pelanggan melakukan satu kali sesi pembayaran (checkout) untuk seluruh keranjang, namun di level database transaksi dipecah menjadi satu `product_orders` per toko beserta `payments` per pesanan toko untuk akurasi rekonsiliasi dan pembatalan parsial. | PRD Bagian 6.3, BRD AB-010 |
| **PK-07** | Penyaluran Dana ke Teknisi & Mitra Toko | Sistem hanya mencatat rekonsiliasi hak pendapatan (`technician_earning` dan `store_earning`). Penyaluran dana aktual ke rekening bank/dompet digital dilakukan manual di luar sistem. | PRD Bagian 14, BRD Lampiran C |
| **PK-08** | Kriteria Verifikasi Teknisi & Mitra Toko | Admin memverifikasi akun teknisi dan mitra toko secara manual melalui Panel Admin Filament berdasarkan kelengkapan identitas, nomor telepon, dan data profil toko/keahlian. Status awal saat mendaftar adalah `menunggu`. Hanya akun `disetujui` yang dapat menerima pesanan / tampil di katalog publik. | PRD Bagian 7 & 8, BRD AB-011 |
| **PK-09** | Kategori Produk Marketplace | Produk dibatasi pada kategori material bangunan, perkakas, dan suku cadang instalasi rumah yang dikelola oleh Admin melalui `product_categories`. | BRD FR-031, PRD 10.1 |
| **PK-10** | Mekanisme Notifikasi | Pada tahap awal, notifikasi menggunakan database notification / in-app flash messages bawaan Laravel/Livewire. Layanan WebSocket/Pusher pihak ketiga opsional pada fase R3. | PRD Bagian 3 (R3), BRD FR-043 |
| **PK-11** | Mode Integrasi Eksternal (Sandbox vs Simulasi) | Mengingat proyek ini berada dalam lingkungan akademik, seluruh interaksi pembayaran dan kurir dijalankan dalam mode simulasi lokal terstandar (Mock Adapter) dengan payload realistis. | BRD 5.6 Asumsi 2 |
| **PK-12** | Wilayah Operasional Awal | Ditetapkan wilayah metropolitan Jabodetabek (khususnya Jakarta - Tangerang) dengan koordinat default geospasial di Tangerang/Jakarta untuk data seeder. | PRD Bagian 10.2 |
| **PK-13** | Visibilitas Status Belanja Material untuk Teknisi | Teknisi hanya dapat melihat pilihan pelanggan: apakah pelanggan memilih "Lihat Marketplace" atau "Lewati Marketplace". Teknisi tidak dapat melihat rincian keranjang belanja atau transaksi rahasia pelanggan di toko material. | PRD Bagian 8 & 14, BRD Lampiran C |
| **PK-14** | Ambang Metrik Kinerja | Waktu muat halaman ditargetkan <= 3 detik pada koneksi lokal/standar. Seluruh kueri Eloquent untuk multi-toko dan komisi wajib menggunakan eager loading guna mencegah masalah *N+1 query*. | PRD Bagian 11 |
| **PK-15** | Biaya Tambahan Jarak dalam Dasar Komisi Jasa | Dibuat sebagai pengaturan sistem di tabel `system_settings` (`service_commission_includes_distance_fee`). Nilai default ditetapkan `false` (komisi 5% dihitung murni dari tarif dasar jasa, kecuali jika pengaturan diaktifkan menjadi `true`). Biaya jarak tetap Rp10.000 jika jarak rute >= 10 km. | PRD Bagian 6.5 & 14, BRD 2.3 |
| **PK-16** | Penanganan Material Tidak Tersedia di Toko | Jika material rekomendasi teknisi tidak ditemukan di toko mitra, pelanggan dapat memilih tombol "Lewati Marketplace" dan membeli mandiri di toko offline tanpa membatalkan atau memengaruhi pesanan jasa. | PRD Bagian 4.2 & 6.1 |
| **PK-17** | Batas Waktu Mengubah Pilihan Lewati ke Lihat | Pelanggan dapat mengubah pilihan dari "Lewati Marketplace" kembali menjadi "Lihat Marketplace" kapan saja selama pesanan jasa belum berstatus `selesai` atau `dibatalkan`. | PRD Bagian 4.2 butir 3 |
| **PK-18** | Pajak & Biaya Tambahan Marketplace | Belum diberlakukan pungutan PPN/biaya platform tambahan selain komisi 2% dari nilai produk. Nilai komisi 2% ditanggung dari porsi toko (toko menerima 98%). | PRD Bagian 6.5 |
| **PK-19** | Pembelian Mandiri di Luar Pesanan Jasa | Pada arsitektur basis data, `service_order_id` pada tabel `product_orders` dibuat `nullable` sehingga di masa depan marketplace dapat dibuka secara mandiri tanpa merusak skema data. Namun alur utama difokuskan pada pesanan jasa. | PRD Bagian 10.1 & 14 |
